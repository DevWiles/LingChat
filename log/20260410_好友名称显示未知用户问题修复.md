# 好友名称显示"未知用户"问题修复

## 问题描述

加好友后，在好友列表或好友申请列表中，对方名称显示为"未知用户"。

## 问题分析

### 根本原因

代码逻辑本身是正确的——`FriendServiceImpl` 会查询 `UserProfile` 表获取好友信息。问题出在**数据层面**：`user_profile` 表中没有对应好友的用户档案记录。

### 为什么数据缺失？

1. **注册流程分离**：注册时 `auth-service` 会调用 `user-service` 创建 `user_profile` 记录
2. **调用失败被吞掉**：`AuthServiceImpl.register()` 中调用 `user-service` 的代码在 try-catch 中只记录日志，不抛异常
3. **用户无感知**：注册正常完成，但 profile 创建失败，用户登录后一切正常，直到加好友时才发现问题

```java
// AuthServiceImpl.java:55-65
try {
    restTemplate.postForObject(userServiceUrl + "/api/user/profile/init", ...);
} catch (Exception e) {
    // 失败时只记录日志，不影响注册主流程
    log.error("初始化用户档案失败...");
}
```

### 直接表现

在 `FriendServiceImpl.convertToFriendRequestResponse()` 中：
```java
UserProfile senderProfile = userProfileRepository.findByUserId(request.getSenderId()).orElse(null);
// ...
.senderNickname(senderProfile != null ? senderProfile.getNickname() : "未知用户")
```

当 `senderProfile` 为 null 时，显示"未知用户"。

## 解决方案

### 代码层面优化

1. **昵称为空时降级到用户名**：即使 profile 存在，如果 `nickname` 字段为空，应显示 `username`
2. **返回用户名字段**：好友申请响应中返回 `username`，前端可做降级显示

### 修改内容

#### 1. `FriendRequestResponse.java` - 增加用户名字段

```java
private String senderUsername;  // 新增
private String senderNickname;
```

#### 2. `FriendInfoResponse.java` - 增加用户名字段

```java
private String username;  // 新增，前端可做降级显示
private String nickname;
```

#### 3. `FriendServiceImpl.convertToFriendRequestResponse()` - 优化显示逻辑

```java
String senderNickname = "未知用户";
String senderUsername = null;

if (senderProfile != null) {
    // 优先显示昵称，如果没有昵称则显示用户名
    senderNickname = senderProfile.getNickname();
    if (senderNickname == null || senderNickname.isBlank()) {
        senderNickname = senderProfile.getUsername();
    }
    senderUsername = senderProfile.getUsername();
}
```

## 后续建议

### 数据修复

对于已存在但没有 profile 的用户，需要手动补全数据：

```sql
-- 查找缺失 profile 的用户
SELECT u.user_id FROM user u
LEFT JOIN user_profile p ON u.user_id = p.user_id
WHERE p.user_id IS NULL;

-- 为这些用户创建 profile 记录
INSERT INTO user_profile (user_id, username, nickname, status, create_time, update_time)
SELECT user_id, username, username as nickname, 0, NOW(), NOW()
FROM user
WHERE user_id NOT IN (SELECT user_id FROM user_profile);
```

### 架构改进建议

1. **注册事务一致性**：考虑使用分布式事务（Seata）或消息队列确保 profile 创建成功
2. **健康检查**：增加定时任务检测并修复缺失的 profile
